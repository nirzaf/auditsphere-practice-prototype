## Closure rules

1. For a parity candidate, the owner must choose implement, accept the simplified representation, or exclude it. Do not convert a table entry into an assumed feature requirement.
2. Any approved implementation needs an observable scenario, role/scope checks, negative/rework coverage, a verification run, and an identified acceptance owner.
3. Keep `docs/prototype/module-coverage.md` and `docs/Progress_Tracker.md` authoritative for current prototype story/test status. This crosswalk maps domains; it does not override criterion status or human sign-off.
